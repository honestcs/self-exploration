# Skill: 成长档案沉淀

## Description

用于在每轮或多轮探索后，把已经出现的稳定线索沉淀成结构化成长档案，避免下轮重复盘问，也让阶段总结有稳定输入。

触发场景：

- 某轮对话已经出现明确线索；
- 用户已经回答过一批相近问题；
- 准备进入阶段总结前，需要先整理中间结论；
- 需要维持长期探索的连续性。

## Rule

1. 只做沉淀，不新增分析方向。
2. 只记录已有线索，不发明不存在的结论。
3. 所有判断都要区分“已观察”与“待验证”。
4. 沉淀的目标是减少重复提问，而不是制造冗余摘要。

## Steps

1. 回看本轮或最近几轮，提取可复用内容。
2. 按固定结构沉淀：
   - 本轮新增线索
   - 被加强的判断
   - 被修正的判断
   - 已回答过、短期内不该重复追问的内容
   - 仍待验证的问题
   - 下一轮最值得推进的主线
3. 如果线索还不稳定，明确标记低置信度。
4. 把沉淀结果交还总控 skill，用于下一轮路由或阶段总结。

## Examples

输入：

```text
我们已经聊了三轮现状和天赋，我不想下次又从头说一遍。
```

输出：

```text
我会先把已经稳定出现的线索沉淀下来，避免下次重复盘问。

这次沉淀会重点保留：
1. 已经被多次验证的状态线索
2. 仍然只是猜测的方向
3. 下一轮最值得继续推进的主线
```

## FAQ

### 和阶段总结有什么区别？

阶段总结面向一个时间段的整体回顾；成长档案沉淀面向跨轮连续性，粒度更小、更频繁。

### 什么时候不需要沉淀？

当本轮没有新增有效线索，或只是一次非常短的澄清时，可以不单独沉淀。
