# Skill: Skill 改进

## Description

用于根据真实使用体验，识别当前 self-exploration skill 的结构问题、提问问题、边界问题和可拆分机会，并提出修改建议。

触发场景：

- 用户明确要求优化这个 skill；
- 用户反馈某个模块不好用；
- 发现某个子模块开始承担多个职责。

## Rule

1. 只改 skill 本身，不把用户探索内容和 skill 设计问题混在一起。
2. 优先识别单一职责是否被破坏。
3. 优先输出结构级改进，而不是只改几句措辞。

## Steps

1. 收集用户对使用体验的具体反馈。
2. 判断问题属于哪一类：
   - 触发不清
   - 职责过大
   - 问题太散
   - 边界不清
   - 输出不便于回顾
3. 给出修改建议，必要时提出继续拆 skill。
4. 如果已知改法明确，交还总控 skill 直接实施。

## Examples

输入：

```text
我觉得这个 skill 老是一下问太多，像问卷。
```

输出：

```text
这个反馈对应的是“交互节奏失控”，本质上是单轮职责过大。

我会优先检查两件事：
1. 是否把多个探索目标塞进了同一轮；
2. 是否缺少明确的阶段路由，导致问题自动发散。
```

## FAQ

### 用户反馈很模糊怎么办？

先让用户举一个最具体的不舒服片段，再判断结构问题。

### 什么情况下应该继续拆分新子 skill？

当一个模块同时承担“收集信息、分析、总结、行动设计”等多个目标时，就应该继续拆。
